# Terminal backends

## Local and SSH persistence

Set `session.persistence = true` to use tmux. MosaicTerm creates a dedicated tmux server and one session per pane. Closing the app or closing a pane detaches its client. **Sessions → End session** stops the selected shell. Enable `session.auto_restore = true` to reopen the previous split layout automatically, or use **Restore previous layout** from the Sessions dialog. MosaicTerm writes pane layout and session identifiers to disk. Recent output comes from tmux and appears as a separate block on reattach. [#132](https://github.com/djdanielsson/mosaicterm/issues/132)

Set `session.ssh_host` to an OpenSSH host or configuration alias, or enter an alias in the Sessions dialog. The remote host needs tmux and Bash. OpenSSH uses the user’s configured identity, agent, proxy, and host-key checks in batch mode. **List sessions**, **Attach**, and **New persistent shell** are separate actions. An interrupted connection leaves the shell running, and attaching to an ended session reports that it is unavailable. [#133](https://github.com/djdanielsson/mosaicterm/issues/133)

Linux tests with tmux 3.5a restored two panes with their original shell PIDs and directories. A loopback test with the system OpenSSH client dropped the connection while a command was running and recovered the missed output and exit code without starting a second shell. Live command boundaries use OSC 133. For MosaicTerm’s managed Bash sessions, tmux also retains the last exit code and whether the shell is idle. A cold restore recovers a bounded screen snapshot and subsequent live output. Full pre-disconnect command history would require a replayable raw stream. Local shells with custom startup arguments use their own integration.

## libghostty-vt overlay

Set `MOSAICTERM_GHOSTTY_VT` to the absolute path to a libghostty-vt 1.x shared library to use the experimental engine for fullscreen programs. MosaicTerm loads it at runtime and uses its existing overlay when loading fails. The engine handles PTY bytes, terminal replies, alternate-screen state, and resize. MosaicTerm renders its styled VT snapshot in the existing overlay and keeps command history outside the engine. [#131](https://github.com/djdanielsson/mosaicterm/issues/131) · [libghostty-vt](https://lib.ghostty.org/vt/)

Tests against the published libghostty-vt 1.0.0 release on Linux checked ANSI color, wide and combining Unicode, a split UTF-8 sequence, cursor replies, and alternate-screen restoration. A live Vim test resized the actual PTY and returned to the original command history after exit. The prototype retains MosaicTerm’s existing keyboard handling. Integration with Ghostty’s selection API remains open. The Linux shared library was built from the official source and dependency archives. Upstream documents macOS and Windows packaging, with native MosaicTerm verification still pending on those platforms. [Release assets](https://release.files.ghostty.org/libghostty-vt/1.0.0/SHA256SUMS) · [Upstream packaging](https://github.com/ghostty-org/ghostty/blob/main/dist/cmake/README.md)

## Rex

Run `python3 examples/rex_backend_probe.py /path/to/rex` on Linux to repeat the isolated evaluation. Rex 0.1.0-preview.21, API revision 18, supported session listing, attachment, terminal input, resize, working-directory events, and a data-stream ticket. A reconnect reached the same running shell and its recent output. `terminal.child_exited` reported code 9 when the shell itself exited. Command completion inside that shell is a separate event tracked by shell markers. [#135](https://github.com/djdanielsson/mosaicterm/issues/135) · [Rex server API](https://www.superlogical.com/rex/docs/automate/server-api) · [Terminal events](https://www.superlogical.com/rex/docs/reference/events)

The restored VT snapshot omitted OSC 133 markers, so the documented snapshot and event APIs could not reconstruct command boundaries and exit codes. The data ticket negotiates `rex.data.terminal.v1`. The probe establishes ticket issuance, while the data framing, ordered raw bytes, and replay guarantees remain unverified. Keep Rex optional and outside the application until those capabilities can be verified. The tested preview publishes Linux, macOS, and Windows builds. [Data API](https://www.superlogical.com/rex/docs/reference/api#dataconnect) · [Preview artifacts](https://blob.superlogical.com/api/releases/rex/preview)
